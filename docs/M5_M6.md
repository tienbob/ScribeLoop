## Recorder behavior and historical local M6 experiment

Record still requires explicit participant permission, source/microphone selection,
and consent. Discovery never opens a PCM source. Native reads and encrypted writes
have their own bounded queue. ASR reads authenticated snapshots of recorded audio;
a slow or failed model does not stop otherwise healthy recording. Stop closes and
finalizes audio independently of ongoing inference.

The superseded local experimental meeting profile uses **MOSS float16 + SDPA**. A persistent
isolated process loads while early audio arrives and serves successive windows;
it is closed on completion/cancellation. There is no implicit CPU/float32/model
fallback or runtime download. Windows contain up to 20 seconds of unconfirmed
audio and up to two seconds of preceding context. Frame starts and gaps remain on
the recorder timeline, including silence, with independent per-stream VAD decisions.
Automatic mode examines bounded early speech once, persists a shared Vietnamese/
English language lock, and uses it for both tracks and the final pass. Uncertain
language detection pauses inference, retaining audio for manual selection/resume.

Provisional text is ephemeral. Segment-level LocalAgreement confirms the unchanged
prefix of two successive hypotheses; timestamps remain model estimates, not word
alignment. Confirmed rows and the per-stream transcription checkpoint commit in
one transaction. Resume includes prior context and removes exact repeated context
only from timestamp-crossing rows. It never restarts microphone capture.

Inference coalesces pending audio into bounded windows. At 60 seconds of backlog,
live inference pauses for that track, recording continues, and the UI explicitly
says processing is deferred until Stop. Float16 remains the default throughout;
this profile does not silently switch to a smaller model. Catch-up consumes the
saved audio after Stop. The five-minute capture bound remains.

Short MOSS windows currently have much worse recognition than the established
full-recording pass. Therefore after live catch-up the app automatically refines
the complete recording using the existing local batch MOSS profile. Live text
stays visible and its revision remains saved. Only a complete successful final
pass becomes the current revision; failure retains the live transcript and audio.
The UI shows refinement separately. This additional pass trades post-Stop time
for final transcript quality; it does not establish live accuracy acceptance.

## Delayed speakers

Community-1 runs on CPU in a separate cancellable local process, using only its
cached model. It processes 30–35 second windows with overlapping context. Temporal
agreement in shared audio anchors a clear identity match; otherwise normalized
embedding cosine/margin thresholds provide conservative matching. Anonymous
embeddings are bounded in memory and are never persisted. On restart, new labels
start after existing label numbers rather than assuming an old identity.

Concurrent speaker turns are retained. Transcript display assigns a speaker only
when one label covers at least 80% of the segment with no competing label;
overlap/uncertainty stays explicit. The microphone remains “Microphone.” These
are segment-level labels, not validated own-voice recognition or word attribution.
A missing/failed diarizer leaves transcription working with unknown voices.
Thresholds and cross-window identity quality still need corpus/real-call validation.

## Recovering an interrupted meeting

Select the failed/interrupted meeting, expand **Saved recording tools**, and choose
**Recover interrupted audio**. Recovery authenticates both original tracks first.
Malformed records, wrong keys, invalid tags, and reordered records fail; only a
missing/incomplete final record is treated as a crash tail. The original strict
full-file reader still rejects unfinalized files.

Recovery writes authenticated complete frames into new encrypted containers with
fresh random file IDs/key derivation/nonces, fsyncs and atomically replaces each
selected recovered file. It never appends using a previous nonce sequence. Original
ciphertext is retained. A crash between track replacements is retryable. Reports
show authenticated end/duration, partial tail bytes, and original completion state;
missing tail duration is unknown. The UI marks recovered audio interrupted.

Then choose a language if necessary and **Resume transcription**. Committed text
remains, and new windows start at each durable confirmation checkpoint. Legacy
batch-only transcripts without checkpoints use **Transcribe again** instead.
Restart itself only marks active sessions interrupted; it never opens a device.

Schema version 2 adds recorded/confirmed/diarized checkpoints and speaker turns;
existing sessions and transcript revisions survive migration. Recorder checkpoints
follow periodic fsync independently of inference. Prefix reads used for inference
also fsync before publishing a recorded boundary. Recovery reconciles recorded
boundaries against authenticated data, without deleting prior confirmed text.

## Deletion and retention

While all recording/processing is idle, explicitly check permanent-delete consent
and choose **Delete selected meeting**. Changing selection clears that consent.
The operation first marks a retryable `deleting` state, retires the audio key,
removes original/recovered ciphertext, and deletes dependent DB rows in foreign-key
order, including summaries, vectors, words, links, speaker turns and checkpoints.
It finishes with a WAL truncate checkpoint. Failure leaves a retryable tombstone;
there is no promise of restoring data after key retirement.

Retention is explicit cleanup, not an unattended scheduler: choose an age (default
30 days), check its separate permanent-deletion consent, and apply it. Only old
idle meeting sessions are selected. Active sessions/readers block retirement.
Backups, previously unlocked external readers and copied keys/ciphertext remain
outside this local deletion guarantee. No real user data was deleted in development.

## Verification and measurements

Tests cover authentication/consent, strict versus prefix reads, tampering,
partial records, fresh encryption identity, retry after partial recovery, migration,
atomic transcript/checkpoint rollback, capture-free resume/deduplication, deletion
retry/retention, independent stream partials, timeline gaps, LocalAgreement,
confirmation before Stop, live-model failure isolation, deferred catch-up, bounded
windows, speaker continuity/ambiguity/overlap and final revision preservation.

A reproducible cached-model check uses only a configured public WAV, duplicates it
to two test tracks with a 150 ms offset, paces it in real time, and writes only an
aggregate report. Temporary encrypted audio and in-memory metadata are discarded.
It opens no physical devices and uses no native user keys.

```bash
.venv/bin/python scripts/check_live_meeting.py \
  --audio data/corpus-v1/moss/segment-300-600-fp16-sdpa.wav \
  --seconds 300 --language en \
  --reference-words data/corpus-v1/investigation/reference-words.json \
  --reference-turns data/corpus-v1/ES2004a.speakers.json \
  --reference-start-s 300 \
  --output data/phase1/live-public-five-minute-final.json
```

Initial five-minute run before final-pass/continuity hardening: first provisional
text 9.11 s, first confirmed text 13.16 s, completion 322.97 s for 300 s input;
live median/p95 partial delay 5.52/22.72 s and confirmation delay 25.59/44.84 s;
live WER 65.84%, diagnostic speaker DER 51.30%, four assigned labels plus unknown
turns. These miss the quality/latency targets; they motivated automatic full-audio
refinement and stronger overlap anchors. Raw aggregate:
`data/phase1/live-public-five-minute.json`. Unknown turns receive unique scoring
labels, conservatively penalizing fragmented attribution. WER/DER are exploratory
AMI mixed-headset metrics, not official scoring or Vietnamese acceptance.
